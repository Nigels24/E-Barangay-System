Bank Reconciliation Statement

Questions 1–10
01
Blocks build

Does every barangay submit a Bank Reconciliation Statement every month, and is it required by COA?

This decides whether the reconciliation is built into the first version or added later. If it is a monthly statutory requirement, it should be designed in now — adding it after the ledger is finished means reworking the ledger.

Blocks build

How many bank accounts does one barangay have?

The books show a single Cash in Bank, but barangays often keep separate SK and Trust Fund accounts. One account per barangay is a single field; several accounts needs its own table — and that is difficult to change afterwards.

Before go‑live

Where does the bank balance come from — typed in from a paper bank statement, or a file from the bank?

The system runs entirely offline with no internet, so a bank feed is not possible. Confirming that the balance is keyed in by hand means the screen can be designed around fast, accurate typing.

Before go‑live

Is the list of reconciling item types fixed by COA, or can the bookkeeper add new ones?

If the list is fixed, it becomes a set of labelled rows that cannot be mistyped. If it can vary, the bookkeeper needs a way to add items.

05
Blocks build

When a reconciling item is recorded, should the system also create the journal entry for it — or does the bookkeeper post that separately?

This is the most important question in this section. A bank service charge or interest credit has to reach the ledger somehow. Either the reconciliation posts it automatically, or it stays a worksheet and the bookkeeper journalises by hand. The two are built very differently, and doing both creates double entries.

Found in br(jan) A −600.00 book-side credit memo annotated “checkbook”, and a −825.00 bank-side item annotated “CK# 3395683 — VAT”. The first is the kind of item that normally needs a journal entry.
06
Blocks build

Should the system track each check as issued and then cleared, carrying unpresented checks forward automatically each month?

The Check Disbursement Journal already records check numbers. If outstanding checks should carry forward on their own, every check disbursement needs a check number, check date and cleared date — which changes that entry screen. If the bookkeeper prefers to list them manually each month, the entry screen stays simple.

Found in UpperSibatangJV2023.xlsx · Check Disbursement Journal w/ CK# 3869301 (02/01/23)  ·  w/ CK# 3869302 (02/01/23) Check numbers are written inside the particulars text rather than in their own column.
07
Confirm

Must the adjusted book balance always equal the Cash in Bank balance in the general ledger for that month — and if they differ, should the system block the reconciliation or simply warn?

Blocking guarantees the two never disagree. Warning lets the bookkeeper save a half-finished reconciliation and come back to it. Most offices prefer a warning.

Blocks build

Do all 54 barangays use one identical chart of accounts, or can a barangay have accounts the others do not?

One shared list means a correction made once applies everywhere. Per-barangay lists mean 54 separate lists to maintain. This affects the structure of the database and is expensive to change later.

Does the number restart at 001 each year, or each month — and is the sequence separate for each book and each barangay?

Needed to generate numbers correctly. With 54 barangays sharing one system, a sequence that is not separated per barangay will collide.

Should check number and check date be required on every check disbursement?

They are currently written inside the description text, which means they cannot be searched or matched against the bank. Giving them their own fields makes both possible — and is required if the answer to question 6 is yes.

Blocks build

Once a month has been closed and certified, should it be locked permanently — or may an administrator reopen it?

A permanent lock is the stronger audit position. Most offices need the ability to reopen for a late correction. If reopening is allowed, it will be recorded in the audit trail with the reason.

Before go‑live

Should the year‑end closing entries be produced by the system, or prepared by the accountant as a general journal entry?

The 2023 workbook contains a closing sheet, so the entries are currently prepared by hand. The system can generate them, but only if the office wants that.

UpperSibatangJV2023.xlsx Sheet clo2023 — closing entries for the year.
27
Before go‑live

Is there a USB drive or external disk the office can keep backups on, and who will be responsible for it?

This is the single largest risk in the whole project. The system runs on one computer with no internet, so all 54 barangays’ books live on one hard disk. The system will back up automatically and check each backup is readable, but a copy kept on the same machine does not survive that machine failing.
